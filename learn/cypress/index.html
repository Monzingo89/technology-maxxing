Cypress

javascript end-to-end testing for web apps

2026 · Daily Agent

Why learn Cypress?

Cypress helps teams ship web apps faster by running reliable browser tests close to real user behavior. It reduces flaky timing issues with automatic waiting/retries, gives fast local feedback, and fits naturally into CI/CD pipelines.

Where it came from

2015: Cypress company formed to rethink flaky front-end testing. 2017: Cypress was open-sourced and adoption accelerated in JS teams. Cypress introduced a built-in Test Runner UX that made debugging easier than many legacy tools. Component Testing matured over time, expanding Cypress beyond only end-to-end checks. Dashboard evolved into Cypress Cloud for team-level analytics and CI optimization.

Build your understanding

Work through these exercises in order. Try the task before opening a reference.

  1. Write one Cypress test that visits your app home page, checks a visible heading, and avoids brittle CSS selectors by using data-cy attributes.
  2. Refactor a login flow using cy.session() so three protected-route tests reuse auth state. Measure runtime before and after.
  3. Given a flaky checkout test, add network stubbing for one unstable API call, set clear assertions, and explain why the new version is more deterministic.
  4. Implement a test for SSO login where identity provider runs on a different domain. Use cy.origin() and verify successful redirect back to the app.
  5. Design a Cypress CI strategy with test splitting and retries. Include when to fail fast, when to rerun, and how to read flake metrics in Cypress Cloud.

Catalog research notes

  • Modern projects use unified cypress.config.* with separate e2e/component sections.
  • cy.session() is widely used to cache login state and speed CI runs.
  • cy.origin() enables safer cross-origin flows (for SSO and third-party auth screens).
  • Cypress Cloud added stronger flake analytics, run insights, and parallelization controls.
