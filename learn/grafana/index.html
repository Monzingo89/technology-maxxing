Grafana

open-source observability dashboards and alerting platform

2026 · Daily Agent

Why learn Grafana?

Grafana gives teams one place to query, visualize, and alert on telemetry from many systems, reducing time-to-detect and speeding incident response.

Where it came from

Started in 2013 by Torkel Ödegaard, initially focused on Graphite-style monitoring dashboards. Grafana 1.0 was released in 2014 and adoption grew quickly in DevOps teams. Grafana Labs formed to maintain Grafana and build a larger observability ecosystem. In 2021, Grafana core licensing moved from Apache 2.0 to AGPLv3. Grafana 8 introduced unified alerting to reduce split alert workflows.

Build your understanding

Work through these exercises in order. Try the task before opening a reference.

  1. Add a Prometheus data source, create one time-series panel for CPU usage, and save the dashboard in a folder named 'team-observability'.
  2. Create a dashboard variable for service name, then build 3 panels (latency, error rate, request volume) that all use the variable.
  3. Create a Grafana managed alert: trigger when 5xx error rate is above 2% for 10m, route it to a contact point, and add runbook link annotations.
  4. Use provisioning files to auto-load one Prometheus data source and one dashboard on Grafana startup. Verify changes survive container restarts.
  5. From a high-latency panel, add links so users can jump to related Loki logs and Tempo traces for the same service and time range.

Catalog research notes

  • Recent major releases improved dashboard rendering speed and navigation UX.
  • AngularJS-based plugins are deprecated; modern plugins are React-first.
  • Unified alerting has matured with better routing, silences, and contact points.
  • Integrations continue to expand across Prometheus, Loki, Tempo, and OpenTelemetry.
