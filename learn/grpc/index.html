gRPC (grpc)

high-performance rpc over http/2 with protobuf

2026 · Daily Agent

Why learn gRPC (grpc)?

gRPC provides fast, strongly-typed service-to-service communication with code generation, streaming, deadlines, and consistent contracts across languages. It reduces API drift and boilerplate compared with ad-hoc HTTP JSON patterns.

Where it came from

gRPC was open-sourced by Google in 2015, inspired by its internal Stubby RPC system. It standardized on Protocol Buffers (proto3) for compact, schema-first messages. HTTP/2 features (multiplexing, headers compression, streaming) enabled low-latency RPC. Ecosystem growth added many languages, interceptors, load balancing, and observability support. gRPC-Web emerged to connect browser apps to gRPC backends through compatible proxies.

Build your understanding

Work through these exercises in order. Try the task before opening a reference.

  1. Create a .proto file with one unary RPC (CreateNote), request/response messages, and correct field numbers. Generate stubs for one language of your choice.
  2. Implement a client call with a 1-second deadline. On timeout, return DEADLINE_EXCEEDED handling and a user-friendly fallback message.
  3. Build a backend with one unary RPC and one server-streaming RPC. Add an interceptor for request logging and include at least one unit test for each RPC.
  4. Add TLS, health checks, and reflection to a small gRPC service. Verify behavior with grpcurl and document one failure scenario and recovery path.
  5. Expose a gRPC service to browser clients using gRPC-Web through Envoy. Demonstrate one request from a web page and one from a native gRPC client.
