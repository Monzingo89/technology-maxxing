Helm

kubernetes package manager for app releases

2026 · Daily Agent

Why learn Helm?

Helm turns raw Kubernetes YAML into reusable, versioned charts so teams can install, upgrade, and roll back applications consistently across environments.

Where it came from

2015: Created at Deis to simplify Kubernetes app deployment. 2016: Helm 2 introduced Tiller for in-cluster release management. 2018: Donated to CNCF, accelerating ecosystem adoption. 2019: Helm 3 removed Tiller and redesigned security/release handling. 2020: Helm became a CNCF graduated project.

  • 2015: Created at Deis to simplify Kubernetes app deployment.
  • 2016: Helm 2 introduced Tiller for in-cluster release management.
  • 2018: Donated to CNCF, accelerating ecosystem adoption.
  • 2019: Helm 3 removed Tiller and redesigned security/release handling.
  • 2020: Helm became a CNCF graduated project.

Build your understanding

Work through these exercises in order. Try the task before opening a reference.

  1. Install an nginx chart into a new namespace called web, then verify release status and list revisions.
  2. Create dev and prod values files for one chart (replicas, resources, service type). Deploy both with clear release names.
  3. Upgrade a release with a bad image tag, detect failure quickly, and roll back to the previous healthy revision.
  4. Package a local chart, push it to an OCI registry, then install it from OCI in a clean namespace.
  5. Add a chart dependency, lock versions, run dependency update, and explain how reproducibility is preserved.

Catalog research notes

  • OCI registry workflows are now a mainstream way to publish and pull charts.
  • Helm 3 remains the active major line, using caller RBAC instead of Tiller.
  • Chart value validation with values.schema.json is widely used in CI pipelines.
  • GitOps tools increasingly consume Helm charts directly for declarative delivery.
