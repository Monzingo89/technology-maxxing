Jest

javascript test runner with mocks and coverage

2026 · Daily Agent

Why learn Jest?

Jest gives teams a fast, standard way to run automated tests, mock dependencies, and measure coverage. It reduces regressions, shortens feedback loops, and plugs directly into CI/CD gates so broken code is blocked before deploy.

Where it came from

2014: Created at Facebook to test React code with minimal setup. 2016: Open-sourced and quickly adopted beyond React projects. Jest 27: jest-circus became the default test runner. Jest 28+: package split and cleanup improved install footprint and maintenance. Recent majors focus on stability, ESM workflows, and CI performance.

Build your understanding

Work through these exercises in order. Try the task before opening a reference.

  1. Create a sum(a, b) function and a Jest test file with 3 cases (positive, zero, negative). Run in watch mode and fix failures.
  2. Test a service function that calls fetch. Mock fetch, assert called URL, and assert transformed JSON output.
  3. Add Jest coverage thresholds to a project and wire them into CI so pull requests fail when lines coverage drops below 80%.
  4. Given an unstable async test, replace arbitrary timeouts with proper async/await and deterministic mocks.
  5. Configure Jest in a monorepo to run only changed package tests locally while full tests run in CI.
