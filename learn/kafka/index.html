Apache Kafka (kafka)

a distributed event streaming platform

2026 · Daily Agent

Why learn Apache Kafka (kafka)?

Kafka lets teams move high-volume event data between systems reliably and in near real time. It decouples producers from consumers, supports replay, and scales through partitioned logs.

Where it came from

Kafka was created at LinkedIn around 2010 for activity/event stream transport. It was open-sourced in 2011 and became an Apache top-level project in 2012. Kafka Connect and Kafka Streams broadened Kafka beyond messaging into integration and stream processing. Current architecture direction centers on KRaft to simplify cluster operations.

Build your understanding

Work through these exercises in order. Try the task before opening a reference.

  1. Create a topic with 3 partitions, send 10 keyed messages, and verify only per-partition ordering (not global ordering). Capture one screenshot or log snippet.
  2. Run two consumers in the same group against a multi-partition topic. Trigger a rebalance by stopping one consumer, then explain partition reassignment in 2-3 lines.
  3. Configure a producer with idempotence and strong durability. Explain why acks=all plus retries improves reliability and what trade-off it introduces.
  4. Sketch a pipeline: DB change events -> Kafka -> stream processor -> analytics store. Name topic keys, retention policy, and failure-recovery strategy.
  5. Simulate consumer failure after processing records but before commit. Restore processing with minimal duplicates; document your commit strategy.

Catalog research notes

  • Recent releases improved operational stability, balancing, and observability for large clusters.
  • Ecosystem usage grew around Kafka Connect, Streams, and managed Kafka services for real-time data products.
