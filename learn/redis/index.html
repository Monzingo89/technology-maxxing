Redis

in-memory key-value store for caching and real-time data

2026 · Daily Agent

Why learn Redis?

Redis provides very fast read/write access for data that must be served in milliseconds, such as caches, sessions, counters, queues, rate limits, and real-time leaderboard/state workloads.

Where it came from

Redis was created by Salvatore Sanfilippo and first released in 2009. The name Redis comes from 'REmote DIctionary Server'. Redis Cluster (hash-slot based sharding) arrived in Redis 3.0. Sentinel became the standard built-in option for Redis high availability/failover in OSS deployments.

Build your understanding

Work through these exercises in order. Try the task before opening a reference.

  1. Build login session storage using SET with EX, GET, and DEL. Add a check that denies access when TTL is expired.
  2. Implement a fixed-window limiter using INCR + EXPIRE per IP. Return remaining requests and reset time.
  3. Use ZADD, ZINCRBY, ZREVRANGE, and periodic persistence settings to support top-N ranking with fast reads.
  4. Create a queue with BRPOPLPUSH (or equivalent pattern), retry handling, and dead-letter tracking.
  5. Use WATCH/MULTI/EXEC or Lua to prevent overselling when multiple buyers hit the same stock key.

Catalog research notes

  • Redis 7.x expanded server-side programmability (Redis Functions) and sharded Pub/Sub improvements.
  • RESP3 adoption has increased across modern Redis clients for richer protocol semantics.
  • Redis Stack workflows (JSON, Search, TimeSeries, Bloom) became common for app-level data features, including vector search.
  • 2024 licensing changes for Redis source code triggered ecosystem shifts, including the Valkey fork.
