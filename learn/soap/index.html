SOAP

xml protocol for contract-first web services

2026 · Daily Agent

Why learn SOAP?

SOAP provides a strict, contract-driven way for systems to exchange structured messages, especially when teams need formal schemas, message-level security, and reliable enterprise workflows.

Where it came from

1998: SOAP 1.0 was introduced by Microsoft, IBM, and partners. 2000: SOAP 1.1 was published as a W3C Note. 2003: SOAP 1.2 became a W3C Recommendation. 2000s: WS-* standards (like WS-Security and WS-Addressing) expanded SOAP in enterprise stacks. 2010s+: REST/JSON became dominant for new public APIs, while SOAP remained in legacy and regulated systems.

  • 1998: SOAP 1.0 was introduced by Microsoft, IBM, and partners.
  • 2000: SOAP 1.1 was published as a W3C Note.
  • 2003: SOAP 1.2 became a W3C Recommendation.
  • 2000s: WS-* standards (like WS-Security and WS-Addressing) expanded SOAP in enterprise stacks.
  • 2010s+: REST/JSON became dominant for new public APIs, while SOAP remained in legacy and regulated systems.

Build your understanding

Work through these exercises in order. Try the task before opening a reference.

  1. Given a SOAP XML message, identify Envelope, Header, Body, and operation element in under 60 seconds.
  2. From a small WSDL snippet, pick the correct operation name, namespace, and required request fields.
  3. Given a Fault response, determine if the issue is namespace mismatch, missing required element, or auth failure.
  4. Choose when SOAP is preferable over REST for a regulated workflow needing strict contracts and message signing.
  5. Review a request and decide which WS-Security header is mandatory for replay protection.

Catalog research notes

  • Core standard is still SOAP 1.2; no newer major version.
  • Most current work is maintenance: security updates, interop fixes, and platform LTS support.
  • Adoption is strongest in legacy enterprise, finance, telecom, and government integrations.
